# v0.1.0 implementation roadmap

> **For agentic workers:** Each slice gets its own detailed task plan, written
> in the bite-sized RED/GREEN format, at the moment its wave starts. This
> roadmap is the structure contract: waves, lanes, gates, slice boundaries,
> interfaces, and stop conditions. Steps use checkbox (`- [ ]`) syntax for
> slice-level tracking.

**Goal:** Ship v0.1.0: alpha separation for common Poiyomi and lilToon
configurations, an opt-in avatar-root component, and visible plain English
refusal reporting.

**Architecture:** Three worktree lanes merge small PRs through the automerge
gate. Foundation wave first (component, trigger, consent), then report and
registration with texture widening, then shader variant coverage, then
validation and release. One mutation path, fail closed, per-slot refusals.

**Tech Stack:** Unity 2022.3.22f1 editor APIs, NDMF 1.14.x lifecycle, NUnit
through the Unity Test Runner, PowerShell 7 for the one bootstrap script.

**Spec:** `docs/superpowers/specs/2026-09-05-0.1.0-scope-design.md` (decisions
V1 to V12). The roadmap argues from the spec. Executors read both.

## Global Constraints

- Fail closed. Unknown means a named refusal. `MustRemainTransparent` is
  absorbing. Classification never exits early on Unknown.
- Programming defects throw. Never a blanket catch mapped to "unsupported".
- One public type per file. File name equals type name. Production types
  internal where possible. Namespaces mirror folders.
- No new dependencies. No third-party version parsing (D5).
- Evidence discipline: immutable captured records, revalidation before
  mutation, source assets never mutated. Only the NDMF build copy and
  AMUSE-owned generated assets change.
- Attestation is pinned data: exact GUIDs, versions, SHA-256 digests from
  official artifacts. Never re-derived from vendor repositories.
- Tests: NUnit constraint model, `Assert.That`. One test class per production
  type, `<Type>Tests`, folders mirror production. Behavior sentences for
  names. A filtered run reporting 0 tests is a failure. Record observed
  counts.
- RED/GREEN: an admission-direction behavior change shows a failing test
  first, for a named plausible wrong implementation, then a minimal fix.
- Every PR: one slice, one objective, from a fresh worktree, into `main`,
  through the automerge gate. A dirty merge stops its lane and reports.
- No Census Lab data leaves the Lab except reviewed aggregates. No private
  names, paths, GUIDs, or per-avatar rows in any commit or document.
- No Unity MCP write without the identity gate: enumerate instances read
  only, verify `Application.dataPath`, pin the exact intended instance.

## Lanes and concurrency

- Lane A (Build): S1, S2, S4, S5 — serialized; these share the plugin and
  apply files.
- Lane B (Semantics): S3b, S6, S7 — S3b runs beside wave 1; S6 and S7 touch
  different files and could overlap, but stay serial inside the lane.
- Lane C (consent): S0, S3 — serialized.
- Wave 3: single lane, S8 to S11 in order.
- Maximum three concurrent worktrees. Every slice branches from current
  `main` at slice start.

## Gates

1. Plan approval (this document) before wave 1.
2. S3b A4 design approval before A4 code.
3. S12 authorization and results review.
4. S13 release go.

## Dirty-merge protocol

A conflict, a red gate, or an unexpected tree change stops the lane. The
controller reports the conflict and waits. No rebase, no force, no autonomous
resolution. Other lanes continue only when unaffected.

## Execution protocol per slice

1. Write the detailed slice plan (bite-sized RED/GREEN tasks, exact files,
   test code) in `docs/superpowers/plans/`, dated.
2. Create the worktree and branch from `main`.
3. Execute tasks; commit per task; PR; automerge gate.
4. Record observed test counts and console output in the PR description.
5. A filtered run reporting 0 tests is a failure. A successful compile is
   never validation.
